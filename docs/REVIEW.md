# Ревью проекта «Иконостас»

Дата: 2026-10-06 · Коммит: `33f85f8` (main)

## 0. Кратко

«Иконостас» — одностраничное статическое приложение: каталог из 238 SVG-иконок с поиском, масштабированием, копированием SVG в буфер и скачиванием файла. Бэкенда, базы данных, переменных окружения и Docker нет.

Кода немного (`src/main.jsx` — 549 строк, `src/styles.css` — 617 строк). Основные риски сосредоточены в трёх местах:

1. **Данные.** Манифест `public/icons.json` расходится с содержимым `public/icons/`: 20 новых иконок не видны в приложении, иконка `calendar` показывает не тот рисунок, у части иконок подозрительные файлы.
2. **Копирование в буфер.** На iOS/Safari и при открытии сайта по LAN-адресу через `http://` копирование ломается без каких-либо сообщений, хотя это основная функция приложения.
3. **Сборка и зависимости.** Все зависимости указаны как `latest`. `@vitejs/plugin-react` установлен, но не подключён. Нет ни линтера, ни тестов, ни CI, ни проверки манифеста.

## 2. Запуск и локальная разработка

Требования: Node.js `^20.19 || >=22.12` (этого требуют Vite 8 и rolldown), npm. Проверено на Node 24.18 / npm 11.16.

```bash
npm ci
```

```bash
npm run dev
```

Dev-сервер стартует на `http://localhost:5173` и слушает `0.0.0.0`, то есть доступен из локальной сети.

```bash
npm run build
```

```bash
npm run preview
```

- Переменных окружения нет, `.env` не используется.
- **Docker-конфигурации нет** (ни `Dockerfile`, ни `docker-compose`). Результат сборки — статика в `dist/`, которую можно раздавать любым статическим хостингом или nginx. Если Docker нужен, хватит двухстадийного образа `node:22-alpine` (сборка) → `nginx:alpine` (раздача `dist/`).
- Сборка проверена: `vite build` проходит за ~0,2 с, бандл JS — 201 КБ (64 КБ в gzip), CSS — 10 КБ.
- Чтобы добавить иконку, положите SVG в `public/icons/` **и** добавьте запись в `public/icons.json`. Без второго шага иконка в приложении не появится (см. П-1).
- `naming-review.html` открывается в dev-режиме по адресу `/naming-review.html`. В production-сборку он не попадает.

## 3. Проблемы

Приоритеты: 🔴 критичные — пользователь получает неверный результат или функция не работает; 🟠 важные; 🟡 мелкие.

### 🔴 Критичные

**П-1. 20 SVG-файлов не попали в манифест, и в приложении их не видно**
`public/icons/` — 258 файлов, а `public/icons.json` — 238 записей. Без записи в манифесте остались: `agent-face`, `agent`, `ai`, `brain`, `card-wireless`, `catalog-ai`, `code-agent`, `cursor-ai`, `face-id`, `feather-ai`, `hand`, `idea-ai`, `keyboard`, `lamp-off`, `lamp`, `pencil-ai`, `pencil`, `sofa`, `square-wareless` (опечатка: *wareless*), `terminal`. Файлы добавлены в коммитах `9d2d870` («новые иконки») и `323b5a2`.
Исправление: добавить записи в манифест и скрипт проверки манифеста (см. раздел 5).

**П-2. Иконка `calendar` показывает календарь с галочкой**
`public/icons.json:416-420` (`1:197`, `calendar` → `calendar.svg`) и `public/icons.json:885-889` (`1:508`, `calendar-check` → `calendar-check.svg`). Файлы `calendar.svg` и `calendar-check.svg` совпадают байт в байт. До `323b5a2` обе записи ссылались на один `calendar.svg`; при переименовании файл скопировали в `calendar-check.svg`, но простой календарь так и не экспортировали.
Исправление: заново выгрузить `calendar.svg` из Figma (node `1:197`).

**П-3. Подозрительные пары «имя → файл» в манифесте, нужна визуальная проверка**
- `public/icons.json:1607-1610` — `message-off` → `circle-plus--222-22.svg`
- `public/icons.json:1600-1603` — `circle-question` → `frame-2147227405.svg`
- `public/icons.json:606-609` — `pin-off` → `pin-1.svg`
- `public/icons.json:1243-1246` — `qr` → `smile-qr.svg`, при этом рядом есть отдельная `smile-qr 1` (`:1124`)
- `public/icons.json:1558-1561` — `cash-dollar` → `cash--131-214.svg`

Всего у 25 записей имя файла не совпадает с названием иконки. Даже там, где рисунок верный, пользователь скачает файл с бессмысленным именем (см. П-6).

**П-4. На iOS/Safari копирование может не работать**
`src/main.jsx:390-393`, `:426-430`. Между кликом и `navigator.clipboard.writeText` выполняется `await fetch(...)` (`getSvg`, `:380`). Safari и WebKit на iOS разрешают запись в буфер только синхронно внутри пользовательского жеста. После `await fetch` жест «протухает», и вызов падает с `NotAllowedError`. Последний коммит посвящён мобильной вёрстке, значит мобильные сценарии для проекта важны.
Исправление: `navigator.clipboard.write([new ClipboardItem({'text/plain': svgPromise})])`, где `svgPromise` — `Promise<Blob>`. Safari такой вариант поддерживает. Другой путь — заранее загружать текст SVG при наведении или фокусе.

**П-5. Ошибки копирования проглатываются, а по LAN-адресу через `http://` копирование не работает вовсе**
`src/main.jsx:426-437`. `copyFromTile` и `copyFromToolbar` не обрабатывают исключения: при любой ошибке появляется unhandled rejection, а пользователь не видит никакой реакции. Скрипт `dev` (`package.json:3`) намеренно открывает сервер на `0.0.0.0`, чтобы проверять сайт с телефона. Но по `http://192.168.x.x` страница не является secure context, `navigator.clipboard` там равен `undefined`, и копирование всегда падает с `TypeError`.
Исправление: обернуть вызовы в `try/catch`, показывать сообщение об ошибке, добавить fallback через `document.execCommand('copy')` или скрытую `<textarea>`.

### 🟠 Важные

**П-6. Скачанный файл получает техническое имя**
`src/main.jsx:386` — `a.download = icon.file`. При скачивании `circle-question` получается `frame-2147227405.svg`, при скачивании `message-off` — `circle-plus--222-22.svg`.
Исправление: `a.download = \`${slug(icon.title)}.svg\``.

**П-7. `URL.revokeObjectURL` вызывается сразу после `click()`**
`src/main.jsx:386-387`. В Firefox и Safari скачивание иногда срывается, если URL отозван в том же тике. Отзывайте его через `setTimeout(..., 0)` или по событию. Кроме того, у `download` нет обработки ошибок.

**П-8. `getSvg` не проверяет `response.ok`**
`src/main.jsx:380`. На 404 или ответ SPA-fallback в буфер или в файл уйдёт HTML страницы ошибки. При копировании `addSvgName` бросит исключение, которое никто не ловит (см. П-5).

**П-9. Загрузка данных без обработки ошибок и без состояния загрузки**
`src/main.jsx:71-80`. При ошибке `fetch('/icons.json')` или невалидном JSON возникает unhandled rejection. Счётчик показывает «0 иконок» и «Ничего не найдено» (`:485`), и это состояние не меняется. Пока данные грузятся, на долю секунды мелькает то же «Ничего не найдено».

**П-10. Абсолютные пути не дают задеплоить приложение в подкаталог**
`src/main.jsx:6-7`, `:28`, `:380`. Пути `/icons.json` и `/icons/...` захардкожены, поэтому на GitHub Pages (`/<repo>/`) или за reverse-proxy с префиксом приложение не заработает.
Исправление: строить пути от `import.meta.env.BASE_URL`.

**П-11. Если `localStorage` недоступен, приложение падает при старте**
`src/main.jsx:306`, `:319`. `localStorage.iconostasScale` читается и пишется без `try/catch`. Если хранилище заблокировано (настройки приватности, некоторые встраивания в iframe), будет брошен `SecurityError`, и вместо приложения пользователь увидит белый экран. Кроме того, значение не проверяется: строка `"abc"` превращается в `NaN`, и на экране появится `NaN%`. `getStoredIcons` (`:16-23`) защищён правильно — ту же обработку нужно применить и здесь.

**П-12. Плагин `@vitejs/plugin-react` установлен, но не подключён**
`package.json:8`, файла `vite.config.*` нет. Следствия:
- в dev-режиме нет React Fast Refresh: любое изменение перезагружает всю страницу и сбрасывает состояние;
- JSX компилируется в classic runtime (`React.createElement`), поэтому нужен `import React` (`src/main.jsx:1`). В бандле 35 вызовов `createElement`.

Исправление: создать `vite.config.js` с `plugins: [react()]` — либо удалить зависимость.

**П-13. Все зависимости указаны как `"latest"`, и они лежат в `dependencies`**
`package.json:7-13`. Воспроизводимость держится только на `package-lock.json` и `npm ci`. Любой `npm install <pkg>` или пересоздание lock-файла молча подтянет новый мажор: так уже случилось с Vite 8, который сменил сборщик на rolldown. Кроме того:
- инструменты сборки (`vite`, `@vitejs/plugin-react`) должны быть в `devDependencies`;
- нет полей `name`, `private: true`, `type: "module"` и `engines`. README (`README.md:38`) требует Node 20.19+, но `package.json` это требование не проверяет.

**П-14. `npm audit`: 3 уязвимости в инструментах сборки**
`nanoid <3.3.18` (high), `source-map-js 1.0.0–1.2.1` (high), `postcss <=8.5.22` (moderate). Это транзитивные зависимости dev-инструментов, в клиентский бандл они не попадают, поэтому реальный риск низкий. Исправляется командой `npm audit fix`. Устаревшие пакеты (`npm outdated`): vite 8.1.5 → 8.3.3, react/react-dom 19.2.8 → 19.3.0, lucide-react 1.26 → 1.52, plugin-react 6.0.4 → 6.1.2.

**П-15. Dev- и preview-серверы открыты в локальную сеть**
`package.json:3`, `:5` — `--host 0.0.0.0`. В публичной Wi-Fi-сети любой желающий может обратиться к dev-серверу. У Vite в последние годы регулярно находили обходы `server.fs.deny`, через которые можно читать произвольные файлы. Безопаснее по умолчанию слушать `localhost`, а для доступа с телефона завести отдельный скрипт, например `dev:lan`.

**П-16. Несогласованные имена в манифесте**
- без префикса `24_icon-fill/` и с пробелом: `smile-qr 1` (`public/icons.json:1124`), `dollar 1` (`:1180`), `euro 1` (`:1187`), `ruble 1` (`:1194`);
- другой префикс: `icon-24/chevron-centred` (`:1145`);
- пробел в имени и в файле: `credit card` / `credit card.svg` (`:39-42`);
- верхний регистр: `SIM` (`:396`);
- смешаны `_alt` и `-alt`: `document_alt_2`, `document_alt_4`, `document-alt_5`…`document-alt_10`, `briefcase_alt`, `catalog_alt`, `globe_alt`, `bell-off_alt`, `coin_down`, `arrow-uturn_alt`, `gear_skeleton`.

Последствия:
- `addSvgName` (`src/main.jsx:56`) записывает имя в `id`. `id="credit card"` и `id="smile-qr 1"` невалидны: XML ID не может содержать пробелы;
- поиск по `document-alt` не находит `document_alt_4`;
- `cleanName` (`src/main.jsx:12`) знает только два префикса.

**П-17. Пользовательские иконки продолжают показываться при выключенной загрузке**
`src/main.jsx:10`, `:304`, `:363`. Флаг `ICON_UPLOAD_ENABLED = false` прячет только кнопку и форму. Иконки, которые пользователь добавил раньше, по-прежнему читаются из `localStorage` и выводятся первыми, а удалить их нельзя. Удаления не было и при включённом флаге.

### 🟡 Мелкие

**П-18. Мёртвый код за флагом**
`src/main.jsx:163-300` (`AddIconPopover`), `:31-48` (`sanitizeSvg`), `:395-415` (`addIcon`), `:446-457`, `:488`, а также около 200 строк CSS (`src/styles.css:60-90`, `:141`, `:249`, `:349-570`, `:601-616`). Всё это попадает в бандл. Если функцию не планируют возвращать в ближайшее время, лучше вынести её в отдельный модуль с ленивой загрузкой или удалить: она останется в истории git.

**П-19. `sanitizeSvg` построен на чёрном списке и неполон**
`src/main.jsx:37-44`. Не обрабатываются `<animate>` и `<set>` с `attributeName="href"`, `<use href="data:…">`, `xlink:href` на внешние ресурсы (трекинг), `style` с `url(...)`, `data:`/`vbscript:` URI. Внутри приложения SVG выводится через `<img src="data:…">`, где скрипты не выполняются, поэтому прямого XSS нет. Но очищенный SVG затем копируется в буфер и может быть вставлен инлайном в чужой код. Если загрузку вернут, используйте DOMPurify с `USE_PROFILES: {svg: true}`.

**П-20. Нарушения доступности (a11y)**
- `src/main.jsx:461-474`: интерактивная карточка сделана через `<article tabIndex=0>` с `aria-expanded`. У `article` нет роли, которая поддерживает `aria-expanded`. Нужен `<button>`.
- `src/main.jsx:157`: 238 элементов с `role="status"`. Текст «Иконка скопирована» всегда лежит в DOM и переключается только классом, поэтому скринридер копирование не озвучит. Достаточно одного общего live-region.
- `src/main.jsx:456`: `aria-controls="add-icon-title"` указывает на заголовок, а не на диалог.

**П-21. Лишние замеры в `IconTooltip`**
`src/main.jsx:121-133`. Каждый из 238 тултипов при монтировании дважды измеряет текст через canvas, вызывает `getComputedStyle(document.documentElement)` и подписывается на `document.fonts.ready`. Всё это повторяется при каждом изменении фильтра для вновь смонтированных карточек. Сейчас это незаметно, но с ростом каталога станет. Ширину можно получить средствами CSS (`width: max-content` и `interpolate-size`) или считать один раз на уровне `App`.

**П-22. Неверное склонение в счётчике**
`src/main.jsx:444`: «1 иконок», «22 иконок». Нужна `Intl.PluralRules('ru')`.

**П-23. Поиск: лишняя работа и нет нормализации**
`src/main.jsx:367`, `:373`. `title`, `file` и `nodeId` дважды попадают в строку для поиска: один раз напрямую, второй — через `tags`. Строка заново собирается при каждом нажатии клавиши. `_`/`-` и `ё`/`е` не нормализуются. Индекс стоит строить один раз в `enriched`.

**П-24. Поля `x`/`y` в манифесте не используются**
Это координаты фрейма в Figma (`public/icons.json`, все записи). Код их не читает, при этом README (`README.md:20`) требует заполнять их при добавлении иконки.

**П-25. `icon-tags.json` пустой**
`public/icon-tags.json` содержит `{}`. Механизм тегов есть, но не используется. Поиск по смыслу («деньги», «оплата») не работает.

**П-26. `naming-review.html` устарел**
- `naming-review.html:185`: внутри захардкожена полная копия `icons.json` на момент до переименований;
- `:77` утверждает, что «Исходный icons.json не меняется», хотя переименования уже применены в `323b5a2`;
- HTML собирается через `innerHTML` без экранирования (`:205-222`).

Это разовый артефакт: его стоит удалить или перенести в `docs/`.

**П-27. Мелочи в `index.html` и корне репозитория**
- `public/favicon.svg` есть, но `<link rel="icon">` в `index.html` отсутствует, поэтому браузер запрашивает `/favicon.ico` и получает 404;
- `.gitkeep` в корне репозитория бесполезен;
- в рабочей копии лежат пустые неотслеживаемые каталоги `.agents/` и `.codex/`.

**П-28. Качество SVG-ассетов**
- 240 файлов имеют `viewBox="0 0 24 25"` и `height="25"`, ещё 18 — `24×24`. Это артефакт экспорта из Figma: иконки неквадратные и смещены на 1 px;
- цвет `#3D3C3A` зашит в 356 местах, `currentColor` не используется ни разу, поэтому после вставки в код иконку нельзя перекрасить через CSS;
- в 60 местах используется `fill="white"` для «вырезов». На цветном или тёмном фоне они будут видны как белые пятна, а не как прозрачность;
- в 16 файлах есть `clipPath` с Figma-идентификаторами `clip0_XX_YY`. Если инлайнить несколько иконок на одну страницу, идентификаторы могут конфликтовать.

**П-29. Мёртвый CSS**
`src/styles.css:240-242`: у `.icon-tooltip` задано `display:block` вместе с `flex-direction`, `align-items` и `gap`, которые без flex не действуют.

## 4. Технический долг и неочевидные нюансы

- **Манифест редактируется вручную, и никто его не проверяет.** Именно отсюда П-1, П-2, П-3 и П-16. Это главный источник проблем.
- **`nodeId` — ключ React и ключ тегов.** Это ID узла в Figma. Если иконку пересоздать в Figma, у неё сменится `nodeId`, и привязанные теги потеряются.
- **Иконки экспортируются из Figma**, видимо, плагином: на это указывают имена `--129-178`, `frame-2147227405` и формат `nodeId`. Скрипта экспорта в репозитории нет, процесс не задокументирован.
- **`id` в скопированном SVG нужен для Figma.** При вставке Figma берёт имя слоя из `id`. Поэтому `addSvgName` нельзя убирать «за ненадобностью», а имена с пробелами (П-16) надо чинить.
- **Копирование работает только в secure context** (`https` или `localhost`). Чтобы проверить его на телефоне, нужен HTTPS-туннель или self-signed сертификат в Vite.
- **`useDockViewport`** (`src/main.jsx:84-115`) компенсирует экранную клавиатуру на iOS и при этом игнорирует pinch-zoom. Код хрупкий, его стоит проверять на реальных устройствах после любой правки CSS дока.
- **Масштаб иконок** реализован через `transform: scale()` на `<img>` (`src/styles.css:133`). Во время анимации Chromium может растеризовать SVG в исходном размере и затем масштабировать картинку, поэтому при 200 % возможна кратковременная «мыльность».
- **Всё приложение лежит в одном файле**: 549 строк, логика, хуки и разметка вместе. Для текущего объёма это допустимо, но тестировать по частям невозможно.
- **Нет тестов, линтера, форматтера и CI.** Регрессии вроде П-4 обнаружатся только вручную.
